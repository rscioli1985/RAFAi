# NIL RAG MVP — Product Requirements Document

## 1. Context & Vision
- **Problem Statement:** Collect and surface reliable answers to Name, Image, and Likeness (NIL) questions by leveraging user-generated discussions and a retrieval-augmented AI agent.
- **Opportunity:** Consolidate fragmented NIL knowledge from Reddit into a structured knowledge base that powers an AI assistant for athletes, agents, brands, and administrators.
- **Product Vision:** Deliver an MVP that automatically harvests NIL-related discussions, curates a set of frequently asked questions, and exposes them through a simple AI chat experience for internal validation before handoff to an engineering team.

## 2. Goals & Success Metrics
- **Goal 1:** Ingest NIL-related Reddit content daily and store it in an operational datastore with minimal manual intervention.
- **Goal 2:** Surface the top NIL questions and related answers via an AI agent with acceptable accuracy for internal review.
- **Goal 3:** Provide an extensible architecture that can transition to production with minimal rework.

**Indicative MVP Metrics**
- ≥5 target subreddits monitored daily.
- ≥80% of newly created NIL-related threads captured within 24 hours.
- Initial answer quality rated “useful” by internal stakeholders in ≥70% of reviewed sessions.
- End-to-end ingestion-to-answer latency ≤1 hour (batch) and ≤3 seconds for interactive responses.

## 3. User Personas & Use Cases
- **Internal NIL Researcher (Primary)**: Needs consolidated insights to understand prevailing NIL questions and sentiment.
- **Pilot End User (Secondary)**: Tests the AI chat agent to ask NIL questions and validate the knowledge base quality.
- **Future Engineering Team (Tertiary)**: Requires clear architecture, APIs, and operational practices to productionize the MVP.

**Key Use Cases**
1. Schedule a daily Reddit ingestion job across defined subreddits.
2. Automatically detect NIL relevance and extract question-answer candidates.
3. Persist raw, processed, and embedding data for analytics and retrieval.
4. Answer user questions via a web-based AI chat agent using RAG.
5. Provide administrative APIs to monitor ingestion health and manage configuration (e.g., subreddit list, scheduling).

## 4. Product Scope
- **In Scope**
  - Reddit data ingestion (pull-based via official API).
  - Data processing: filtering, topic tagging, FAQ curation.
  - Storage: PostgreSQL (operational datastore) and vector database for embeddings.
  - Backend services: REST API to expose data, retrieval pipeline, and streaming-friendly endpoints for the AI agent.
  - Frontend: minimal React app backed by Node/Express for proxying API calls and hosting chat UI.
  - Configuration & secrets: .env for runtime configuration; YAML-formatted secrets stored outside repo and referenced via absolute paths.
  - Cron-compatible scheduler for daily ingestion.

- **Out of Scope (MVP)**
  - Non-Reddit data sources (e.g., news, Twitter).
  - Advanced moderation workflows or human-in-the-loop review tooling.
  - Production-grade analytics dashboarding.
  - User authentication/authorization beyond basic access controls.

## 5. Functional Requirements

### 5.1 Data Ingestion & Processing
- **FR-1:** Maintain a configurable list of subreddits associated with NIL topics.
- **FR-2:** Retrieve new threads and comments since the last run using Reddit API credentials stored in secrets YAML.
- **FR-3:** Deduplicate content by Reddit ID and store ingestion metadata (timestamp, source, text length).
- **FR-4:** Apply NIL relevance heuristics or keyword models to filter out irrelevant content.
- **FR-5:** Identify frequently asked questions by clustering or heuristic tagging (e.g., question detection, upvote threshold).
- **FR-6:** Extract or summarize high-signal answers for each question using LLM-assisted summarization.
- **FR-7:** Persist raw text, metadata, and derived FAQ records in PostgreSQL.
- **FR-8:** Generate text embeddings for relevant documents/questions and store them in the vector database with references to Postgres records.

### 5.2 Scheduling & Operations
- **FR-9:** Provide a cron-compatible entry point (CLI script or task runner) that can be invoked daily.
- **FR-10:** Log ingestion outcomes and errors; store job status in Postgres for observability.
- **FR-11:** Support manual re-run for a given timeframe to backfill missed data.

### 5.3 Retrieval-Augmented Generation Pipeline
- **FR-12:** Expose an API endpoint that accepts a user query and returns a streamed answer generated by an LLM leveraging retrieved context.
- **FR-13:** Retrieve top-k relevant documents from the vector database and fetch full context from Postgres.
- **FR-14:** Compose prompts that include query, context snippets, citation metadata, and response instructions.
- **FR-15:** Return structured responses: generated answer, cited Reddit links, confidence score, and latency.

### 5.4 Backend APIs
- **FR-16:** Provide REST endpoints for:
  - Managing subreddit list (CRUD).
  - Triggering ingestion job manually.
  - Querying FAQ catalog (filter by topic, recency).
  - Serving AI chat responses (supports streaming).
- **FR-17:** Implement authentication via API keys stored in secrets directory (MVP-level security).

### 5.5 Frontend AI Agent
- **FR-18:** Implement a minimal React interface with chat UI, sourced through a Node/Express backend.
- **FR-19:** Stream assistant responses to the UI for conversational feel.
- **FR-20:** Display cited Reddit sources and ingestion timestamps alongside each answer.
- **FR-21:** Capture feedback rating (useful/not useful) to send back to backend for quality tracking.

## 6. Data Design
- **PostgreSQL:** Tables for `raw_posts`, `raw_comments`, `faqs`, `ingestion_runs`, `feedback`.
- **Vector Database:** Collection storing embeddings with references (`faq_id`, `document_id`), embedding model version, and metadata (subreddit, date).
- **Secrets Management:** Absolute paths to YAML files providing Reddit API keys, OpenAI/LLM credentials, and API auth tokens; environment variables in `.env` reference those paths.

## 7. Technical Architecture
- **Services**
  - `ingestion_service`: Python scripts or worker responsible for calling Reddit API, processing data, and writing to Postgres/vector DB.
  - `backend_api`: Python (FastAPI recommended for async & streaming support) exposing REST endpoints and orchestrating RAG pipeline.
  - `frontend_app`: React UI served via Node/Express, proxies API calls to backend.
- **Infrastructure**
  - Dockerized Postgres instance for local development; compose file to manage dependencies.
  - Vector DB options (e.g., PostgreSQL pgvector extension, Weaviate, Pinecone); choice impacts hosting considerations.
  - Scheduler via system cron or containerized cron job invoking ingestion script.
- **LLM Provider**
  - Initially use hosted API (e.g., OpenAI, Anthropic). Credentials stored via secrets management approach above.

## 8. Non-Functional Requirements
- **Performance:** Ingestion jobs complete within 30 minutes for target subreddits; query response streaming starts within 2 seconds.
- **Reliability:** Job retries on transient Reddit/API failures; at-least-once ingestion guarantee with idempotent writes.
- **Security:** Secrets remain outside repository; .env file lists paths only. API endpoints require auth token. Log redaction for sensitive data.
- **Scalability:** Architecture supports adding additional data sources and more frequent ingestion with minimal changes.
- **Maintainability:** Clear module boundaries, typed Python code, logging/monitoring hooks.

## 9. Operational Considerations
- **Monitoring:** Capture metrics for ingestion success/failure, API latency, vector DB query volume.
- **Alerting:** MVP-level alert via email/slack webhook on ingestion failure.
- **Testing:** Unit tests for ingestion transformers, integration tests for API endpoints, smoke tests for chat flow.
- **Documentation:** README updates for setup, `.env` template, API contract docs, onboarding notes for future engineering team.

## 10. Release Milestones
1. **Milestone 1 — Data Ingestion Foundations**
   - Reddit API integration, Postgres schema, daily cron job, secrets wiring.
2. **Milestone 2 — FAQ Curation & Vector Store**
   - Relevance filtering, FAQ extraction, embeddings pipeline, vector DB integration.
3. **Milestone 3 — RAG API**
   - FastAPI service with retrieval + response streaming; basic admin endpoints.
4. **Milestone 4 — Frontend Agent**
   - React chat UI, Node proxy, response streaming, feedback capture.
5. **Milestone 5 — Pilot Readiness**
   - End-to-end testing, monitoring, documentation, stakeholder review.

## 11. Risks & Mitigations
- **Reddit API rate limits:** Implement backoff, caching, and configure scheduled runs during off-peak hours.
- **Data quality variance:** Combine heuristic filters with LLM summarization and enable manual feedback loop.
- **LLM cost/latency:** Cache embeddings and retrieve minimal context; explore local models for future phases.
- **Secrets leakage:** Enforce `.gitignore` rules, rely on external directories, document rotation procedures.
- **Scalability to production:** Modularize services, ensure Docker compatibility, keep interfaces documented for handoff.

## 12. Assumptions
- Reddit API credentials are available and usage complies with terms of service.
- MVP can rely on managed LLM APIs; no requirement for self-hosted models initially.
- Stakeholders will review and triage FAQ outputs weekly to validate quality.
- Engineering team handoff will occur after MVP validation with documentation in place.
